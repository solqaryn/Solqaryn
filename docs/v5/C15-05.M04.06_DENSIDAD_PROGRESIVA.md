# C15-05.M04.06 — Densidad, carga progresiva y percepción de ligereza

## A0 — Riesgo R1, alcance y límites

Superficie: Angular standalone privado \`/plataforma/auditoria-operativa-v5\`. Este incremento agrega pruebas Playwright reales y workflow dirigido; NO cambia API, esquemas MySQL/EF, JWT, RBAC, tenant, permisos ni contenido de producción. Los HTTP de sesión se simulan exclusivamente dentro de Chromium en el runner GitHub-hosted. El componente nunca consulta PLAN/COLA/DAG/BITACORA en vivo.

Criterios comprobables: (a) 320, 390, 768, 1280 px sin overflow horizontal mayor a 2 px, solo cuatro tarjetas y sin controles de aprobación; (b) espera perceptible mediante role=status, botón deshabilitado y panel privado oculto cuando se revalida; (c) caso 503 sin spinner perpetuo, sin exposición de mensaje remoto y con reintento; (d) caso 403 que retira el panel. Reducir movimiento se prueba con prefers-reduced-motion. La percepción subjetiva de ligereza no se inventa como métrica: aquí se verifican proxies de densidad, progresión y recuperación, NO latencia web real, Core Web Vitals ni presupuesto de performance.

## A1–A3 — Regresiones causales

\`frontend/e2e/c15-05-m04-06-density-progress.spec.ts\` contiene cuatro casos: positivo responsive y frontera de ancho, espera adversarial sin doble solicitud, 503 con recuperación, 403 tras revocación y diagnóstico secreto que nunca debe renderizarse. La prueba de carga retiene la segunda solicitud de sesión en memoria y verifica estado accesible antes de liberarla. No se realizan POST/PUT/PATCH/DELETE ni se escriben datos reales.

A2: denegación de interfaz con sesión sintética. JWT firmado, RBAC HTTP y aislamiento empresarial MySQL A/B NO_APLICA a este changeset de solo pruebas frontend; otros scopes deben acreditarlos por separado. A3: Chromium/Playwright real en runner GitHub-hosted, no capturas falsas ni mocks presentados como backend real.
