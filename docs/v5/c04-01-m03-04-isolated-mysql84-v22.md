# C04-01.M03.04 - adaptador aislado MySQL 8.4 (V22)

## Alcance y riesgo
Microtarea C04-01.M03.04, unica EN_PROGRESO DEV05, R2. Se elige la alternativa explicita de PLAN D: **adaptador aislado**. No existen entidades o migraciones SaaS comerciales ya operativas verificadas en AppDbContext; introducir tablas/producto o activar cobros fuera de este alcance seria un riesgo R3. La implementacion es un adaptador de solo lectura, sin registro en DI productiva, sin cambiar esquema real, migraciones, JWT, permisos ni secrets. El constructor requiere una fabrica DbConnection explicitamente proporcionada, que en CI apunta solo a MySQL 8.4 efimero.

## A0/A1/A2/A3
Una transaccion MySQL REPEATABLE READ consulta por parametros numericos tenant/plan una tabla aislada V22C0401SnapshotIsolated con filas de version de plan, vigencia UTC, suscripcion, capacidad y cuota. Un solo resultado verificable por tenant/plan, nunca LIMIT 1 para resolver datos ambiguos. No modifica ni consume cuota. Rechaza IDs no positivos, ausencia, duplicados de capacidad, tenant discrepante, version invalidada y fallo SQL con null, sin exposicion de detalles. CancellationToken se propaga. El contrato no admite mas de una capacidad para ese tenant/plan: duplicados => deny. Domain aplica nuevamente limites, version, RBAC verificado y tiempo, sin autorizar escrituras ni pagos.

La prueba CI nueva debe ejecutar **real** MySQL 8.4 ephemero, aserciones de tenant A/B, cambio de suscripcion revocada, revision de version, lectura por tenant filtrada, rollback no persistido, caso de capacidad duplicada y denegacion default. El harness crea el esquema exclusivamente en la instancia efimera y nunca emite DDL sobre Aiven real. Requiere TRX ejecutado y cero fail/skip/notExecuted; para A4 ademas Backend Release, seguridad, Scope Lock y V5 exact SHA.

## Limites y continuidad
Este adaptador no esta registrado en la API comercial y no presupone un esquema SaaS productivo. No certifica JWT HTTP/RBAC de la ruta del adaptador nuevo, consumo transaccional con CAS, provisiones, reconciliacion, PSP/recibos, versionado de tarifas en produccion, ni integracion MySQL Aiven. Una implementacion productiva necesita schema/migracion reversible aprobados, autorizacion por usuario y pruebas HTTP signed JWT tenant A/B y rollback. Por tanto aun con CI exitosa, A0-A4 del cierre de fase global y cualquier A5 siguen pendientes hasta revalidacion causal y decision del alcance concreto. M03.05 y M03.06 no se habilitan por mera existencia de un adaptador aislado sin A5 real. Rollback: git revert del commit serial, sin force-push, y DB efimera descartada automaticamente.
