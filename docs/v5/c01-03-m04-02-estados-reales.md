## V30 DEV05 — respuesta de mutaciones con acceso revocado o resultado desconocido (23 noviembre 2026)

- **Brecha funcional R1/R2 corregida en Angular:** antes de este incremento, PUT/logo con HTTP 401/403 mostraba el error genérico, sin diferenciar revocación de sesión/permiso; ante 5xx/timeout, la UI tampoco distinguía un resultado desconocido de una operación no aplicada. El servidor puede confirmar una escritura y fallar antes de responder: un reintento ciego puede duplicar la acción.
- **Nuevo contrato de estado real:** mutaciones PUT/logo HTTP 401→session, 403→forbidden, 404→not-found, 429→throttled bloquean el formulario obsoleto. HTTP 0/5xx→unconfirmed exige recargar el estado del servidor antes de reintentar; no afirma que el cambio se deshizo. HTTP 409/412 mantiene control de conflicto/recarga por versión. No se muestra `err.error.message` ni secretos en DOM.
