# C14-01.M04.04 — Navegación, mensajes y doble acción segura (V19)

## A0 — Alcance e impacto
Verificar en Chromium la ruta privada existente `/plataforma/qa-global-v19` de C14-01.M04.01. Cambios limitados a esta prueba Playwright, su workflow dirigido, esta evidencia documental y CHANGELOG. No modificar `app.routes.ts`, componente Angular ni archivos de las microtareas M04.01/M04.03/M04.05 en desarrollo de otras Tasks. Riesgo R1 de aceptación UI *read-only*; si la implementación futura introduce mutaciones, reevaluar R2 antes de afirmar doble submit.

## A1 — Casos que pueden fallar
Tres pruebas reales en Chromium: (1) acceso anónimo y respuesta sintética 403 desvían a login, no renderizan contenido QA ni secreto; (2) sesión sintética de admin presenta exactamente cinco `NO_VERIFICADO`, aviso SUCCESS solamente como contrato, enlace externo con noopener y cero controles `button/form/input/textarea/select` en panel; (3) navegación con Tab real + Enter y click posterior sobre `Volver a plataforma`, dos visitas y cero solicitudes mutantes originadas mientras la superficie QA es visible.
La UI actual *no tiene formularios ni botones que envíen solicitudes*: comprobar su ausencia es un negativo pertinente; no se inventa una prueba de deduplicación de POST de un formulario inexistente. La prevención de doble acción aquí consiste en no ofrecer controles de cambio ni emitir escrituras, no en certificar idempotencia backend.

## A2 — Seguridad / tenant
`plataformaGuard` y la sesión de browser solo prueban rechazo UX, no JWT firmado, RBAC del servidor, aislamiento real A/B ni permisos nuevos. El payload sensible del 403 es deliberadamente sintético y debe permanecer oculto. La fuente autorizada sigue siendo backend.

## A3 — Integración pertinente
GitHub-hosted Node 24, npm 11, Angular 22 y Playwright/Chromium con servidor loopback real. Tests con sesión simulada explícita. No integra MySQL, EF, API real ni servicios productivos; estos son NO_APLICA a esta regresión de UI read-only, no un PASS supuesto.

## A4, A5 y rollback
Solo certificar tras SHA exacto, tres casos Chromium, Angular lint/build, `verify-solqaryn-project-scope`, V5 y comprobaciones de seguridad pertinentes en SUCCESS. `QUEUED`, `IN_PROGRESS`, `CANCELLED` o `SKIPPED` no acreditan una prueba requerida. BITACORA y PLAN/COLA/DAG deben tener readback. A5 independiente de otra Task Javier. Rollback mediante revert no destructivo; sin QA/main/PROD ni cambios a fórmulas, secretos o datos.
