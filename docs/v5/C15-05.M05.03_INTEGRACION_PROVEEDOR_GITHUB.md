# C15-05.M05.03 — integración real del proveedor GitHub Checks

## A0 y riesgo R2
Se ejercita el proveedor externo GitHub Actions Checks API, pertinente a la auditoría V5, desde un runner Ubuntu GitHub-hosted con token efímero solo de lectura (permissions: contents:read y checks:read). Se agregan una suite Node sin dependencias y un workflow; no se modifican runtime, JWT, API, EF, MySQL, frontend, tenants, secretos ni cuentas productivas. Solo se permite GET de los check-runs del SHA exacto del repositorio solqaryn/Solqaryn.

## A1 y A3 — casos reproducibles
La suite ejecuta siete pruebas Node:test: acceso HTTPS REAL al proveedor, con respuesta no vacía y SHA idéntico, más casos positivos y adversariales de checks SUCCESS, SKIPPED, CANCELLED, IN_PROGRESS, FAILURE, check ausente, SHA ajeno, retry posterior fallido, repo inválido, SHA inválido, HTTP 403 y página incompleta. Solo el primer caso es red real; las fallas negativas son fixtures deterministas. El workflow obliga 7/7 PASS y 0 FAIL, y ejecuta Scope Lock antes de instalar dependencias. No confundir respuesta HTTP 200 con aprobación CI.

## A2 — Seguridad
No se escribe ni muestra el token en logs. Transporte exclusivo HTTPS a api.github.com, método GET; permisos mínimos read, repository y SHA estrictos, respuesta de más de 100 checks sin paginar o incompleta falla cerrado. No se certifica JWT firmado, permisos RBAC de la app, aislamiento MySQL A/B ni despliegue: no aplican al changeset de test de GitHub.

## A4, A5 y rollback
Registrar el SHA publicado, CI de prueba dirigida, Scope Lock y procedencia V5 en SHA exacto; QUEUED, IN_PROGRESS, SKIPPED o FAIL no son PASS. VALIDANDO se conserva mientras corra CI. A5 requiere otra Task Javier distinta de DEV05, con revisión independiente de código, tests y logs. Rollback normal git revert de dev, sin tocar QA/main/PROD.
