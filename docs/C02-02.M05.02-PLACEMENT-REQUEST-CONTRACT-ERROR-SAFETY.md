# C02-02.M05.02 — contrato Application/DTO de placement y errores seguros

**Alcance:** SOLQARYN dev, PROJECT_SCOPE_LOCK=STRICT, riesgo R2 (aislamiento tenant, JWT/RBAC y selección de almacenamiento). Se ejecutan pruebas xUnit sobre el contrato real `C0202PlacementApplicationGate.Request`, su respuesta `Result` y `IC0202PlacementEvidenceReader`. No existe aquí un endpoint HTTP de placement certificado; no se afirma una prueba HTTP ni una migración.

## A0: rutas, impacto y límites

- El nuevo archivo de pruebas verifica el contrato Application ya existente sin cambiar su implementación ni el modelo Domain, EF, MySQL, API, routing, permisos o DI.
- Un tenant y SHA de solicitud no constituyen identidad: el lector fiable server-side es obligatorio; las denegaciones ocurren antes de consultar datos en solicitudes malformadas.
- Ningún veredicto concede `AuthorizesConnection`, `AuthorizesMigration`, `AuthorizesCutover` o `AuthorizesProduction`.
- Rollback: revert normal del commit de prueba/documentación, nunca force-push ni cambio de estado institucional sin CAS.

## A1/A2: matriz causal

- Positivo limitado: solicitud y evidencia sintéticas coherentes producen `AUTHENTICATED_STORAGE_ADAPTER_REQUIRED` sin autorizar conexión.
- Negativos: tenant con barra, espacio, salto, Unicode invisible, vacío; DTO nulo, modo desconocido o SHA corto; DSN del cliente, esquema destructivo, dual-write/cutover y fallback cruzado; owner B con solicitante A, fuente SHA obsoleta y alias forjado.
- Errores: excepción de proveedor con texto sensible y cancelación no solicitada deben traducirse a código fijo sin filtrar DSN/tokens; cancelación real solicitada debe propagarse sin lectura externa.
- Casos de frontera: IDs invalidos, revisión del contrato y firmas de tipos compilados por .NET 10 xUnit; no inferir JWT real por flags sintéticos.

## A3/A4/A5

- A3: integración HTTP/MySQL/EF/DSN real = **NO_APLICA a esta suite** porque el contrato probado es Application en memoria, no hay endpoint de placement registrado para esta unidad y no se ha modificado infraestructura. El proveedor del test es sustituto controlado exclusivamente para demostrar manejo de errores, nunca certificación de proveedor vivo.
- A4: exigir build/tests .NET10 en GitHub-hosted, controles de seguridad aplicables, `verify-solqaryn-project-scope` y V5 SUCCESS sobre el SHA publicado; `queued/in_progress/skipped/cancelled` no son PASS. BITACORA y PLAN/COLA/DAG requieren readback por ID.
- A5: revisor de una Task Javier distinta debe revisar de manera independiente código, asserts adversariales y límites antes de cualquier aprobación. No QA/main/PROD, no despliegue, no DSN real ni autoridad de storage.
