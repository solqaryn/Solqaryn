# N4.11.H.4 — CentroCosto: límites de seguridad verificados

## Alcance

Este documento registra únicamente controles observables en el árbol vigente de `Desarrollo` para CentroCosto. No certifica despliegue, Producción ni aislamiento multi-tenant que no esté implementado en este módulo.

## Autenticación y autorización

`CentrosCostoController` está protegido con `[Authorize]` a nivel de controlador. Cada operación aplica además `RequierePermiso` sobre `ModuloSistema.Finanzas` con la acción correspondiente:

- lectura/búsqueda y detalle: `AccionPermiso.Ver`;
- creación: `AccionPermiso.Crear`;
- actualización: `AccionPermiso.Editar`;
- activación: `AccionPermiso.Activar`;
- desactivación: `AccionPermiso.Desactivar`;
- eliminación lógica: `AccionPermiso.EliminarLogico`.

Por tanto, el límite RBAC vigente de CentroCosto reutiliza explícitamente el módulo `Finanzas`; no está en estado pre-RBAC y no requiere inventar un módulo `CentrosCosto` para describir el comportamiento actual.

## Reglas fail-closed verificadas

La capa de aplicación valida las asociaciones antes de crear o actualizar:

- cuando `TipoCentroCosto.Sucursal`, `SucursalId` es obligatorio y debe ser mayor que cero;
- para cualquier otro tipo, `SucursalId` debe ser nulo;
- el código se normaliza a mayúsculas y se rechaza un código duplicado activo;
- los fallos de persistencia en crear, actualizar o cambiar estado generan `BusinessRuleException` en lugar de declarar éxito;
- `GetById`, `Update`, activar/desactivar y eliminación lógica devuelven resultado no encontrado cuando el registro no existe.

## Auditoría

Las mutaciones exitosas registran auditoría mediante `IAuditoriaService` bajo `ModuloSistema.Finanzas`, incluyendo acción y entidad afectada. Se registran creación, edición, activación/desactivación y eliminación lógica con los datos de negocio pertinentes.

## Aislamiento de datos

No se declara aislamiento por `EmpresaId` para CentroCosto porque el repositorio vigente no aplica un filtro `EmpresaId` en `GetByIdAsync`, `GetByCodigoAsync`, `BuscarAsync`, `GetActivosAsync` ni `ExisteCodigoAsync`, y el servicio no inyecta un identificador de empresa en dichas consultas.

Consecuencia: cualquier requerimiento de aislamiento multi-tenant por empresa para CentroCosto debe tratarse como gap separado y no como capacidad ya certificada.

La revisión se realizó contra:
